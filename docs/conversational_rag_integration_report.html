AI Art Critic - Conversational RAG & LLM Integration

This document explains how I added the conversational part of the AI Art Critic app. The goal was to let users talk about the artwork they uploaded, with an AI "critic" that can help users with questions they have about the work, while sounding like a meseum guide/art expert.

This belongs to model interaction and adaptation because I integrated the trained model with an LLM.

Overview

1. What I Added

The app already had a local model that predicts style and artist. I added a second layer around it: an LLM-based critic that can explain the result, answer follow-up questions, and use retrieved museum records as extra context of how it needs to talk.

2. Final App Flow

The final solution is not just one model. It is a small AI system where each part has a clear job.

UploadUser uploads artwork image
AnalyzeTest 13 predicts style and artist
EnrichLLM adds title, mood, context, and visible observations (takes over previous step if confidence is low)
RetrieveRAG finds useful local museum records
ChatUser talks with the art critic
The local museum records are used as reference material. They are not treated as the uploaded artwork itself. The LLM can still use its general art-history knowledge, but the retrieved records give it concrete museum examples.

Structured Development

3. Development Steps

  1. I first integrated the final Test 13 model into the Flask backend, so the app could return style, artist and confidence scores.
  2. I added LLM enrichment after the local model. This gives the UI extra fields like time period, emotional tone, display title, and visual observations. It also takes over style and artist predictions if the local model is uncertain.
  3. I added a chat endpoint so the user could ask follow-up questions about mood, brushwork, composition, symbolism, context or any other aspect.
  4. I improved the chat with RAG, so answers are not only generic LLM text but can get information from real museum records I chose.
  5. I replaced my first AI generated local corpus (this is a collection of information used by the AI) with real open-access museum data, because that is safer and more professional for a public app.
  6. I tested the conversation behavior and adjusted the prompt so retrieved museum records can be used as comparisons.

RAG and LLM Behavior

5. How the RAG Works

The app does not send the full museum dataset to the LLM. Instead, it searches locally and only sends a few relevant snippets. This keeps the prompt smaller and makes the answer more focused.

  1. The user's message is combined with the artwork profile, such as predicted style, mood, and visual observations.
  2. The local retriever searches things like style notes, technique notes, ArtEmis emotional examples, and museum records.
  3. The best results are chosen so one source does not destroy the original prompt.
  4. The LLM receives the artwork profile plus selected content from the retriever and writes the answer.

6. Low-Confidence LLM Handoff

The local model stays in control when it is confident. If confidence is low, the app can ask the LLM to help with the final artist or style. This is useful because the local model is trained on a speific dataset, which means if an uploaded artwork has a style or artist that is not present in the dataset, the local model will be uncertain and ofter wrong. The LLM has much more knowledge and because of that is often better in those specific cases.

Short snippet from backend/open_world_artist.py
needs_artist_fallback = not high_confidence

if use_llm and (needs_artist_fallback or style_low_confidence or enrich_analysis):
    llm_result = refine_with_llm(
        candidates=candidates,
        retrieval_hits=retrieval_hits,
        style_hint=style_hint,
        model_confidence={
            "top1": top1_prob,
            "top2": top2_prob,
            "margin": prob_margin,
            "style_top1": style_top1_prob,
        },
        image=pil_image if llm_with_image else None,
    )

    if needs_artist_fallback:
        if llm_result.get("is_unknown"):
            final_artist = "unknown"
        else:
            final_artist = llm_result.get("artist", final_artist)

    if style_low_confidence and llm_result.get("style"):
        final_style = llm_result.get("style", final_style)
This does not mean the LLM always overrides the model. It only happens when the confidence checks say the local model is uncertain, or when extra enrichment fields are needed for the user interface.

7. Prompt and Behavior Rules

The prompt was changed several times because the first version was too generic. The final version tries to make the critic helpful, but also careful. It tells the LLM to:

  • stay grounded in visible evidence, like color, composition, brushwork, light, focal points, and mood (all important inside artworks)
  • avoid overclaiming the artist, intent, symbolism, or exact history (since that could make the response less reliable)
  • treat ArtEmis examples as emotional contexts (since these were written by actual critics), not factual evidence about the uploaded artwork;
  • use retrieved museum records as context or comparisons, not as proof that the uploaded artwork is that exact work;
  • separate local museum references from broader art-history knowledge the LLM has

Security, Privacy, Ethics, Compliance

9. Security and Privacy

  • The OpenAI API key is loaded from environment variables and is not stored in frontend code.
  • The uploaded image is processed by the backend for analysis, but the app does not add permanent user image storage.
  • Chat sessions are short-lived in backend memory and are pruned after a time limit.
  • The frontend sends an `artwork_id` for chat instead of resending the full analysis each time.

10. Ethics and Compliance

The app needs to be careful because the AI critic could make claims about artworks that are not completly true. I added uncertainty handling so the critic can say that a style or artist is only a possibility when confidence is low.

Risk Mitigation
False artist attribution The prompt tells the LLM to avoid strong artist claims when confidence is low.
Hallucinated museum evidence Retrieved records are included as references, and the prompt says not to treat them as the uploaded artwork.
Copyright or license problems The scripts only use museum records that are free to use, and they do not download any copyrighted data
Overly confident interpretation The critic is instructed to connect claims to visible evidence and use careful language to not make it sound like facts.

12. Conclusion

The final result is an AI art critic that combines a trained local model with an LLM users can chat with. The local model gives predictions, the sometimes takes over and explains them, and RAG gives the chat concrete museum examples to work with.

I also adapted the system during development, I first used a generated local corpus (gnerated with AI), then replaced it with real open-access museum records to make the solution more accurate.

This shows a structured development process: build a working version, test the behavior, identify risks and make improvements to finally have a nice working app.
