AI Art Critic - Model Development & Adaptation

This document shows how I built, tested, and slowly improved a model I trained across 13 tests. The focus is on model interaction & adaptation: developing and testing an AI solution step by step, making sure each change actually helped before deciding to keep it or make a change.

Each experiment changed one or two things at a time so I had a clear idea if what I did was actually helping or not. Security, privacy, ethics, and compliance are also covered at the end.

13 experiments ResNet → ViT → DINOv2 53% to 78.3% accuracy Two-stage fine-tuning Multitask learning Final style + artist model

Overview

1. Development Process

Rather than picking the most complex approach straight away, I had to get familiar with how the training would work, which is why I started with resnet18 The idea was to always have a fast working starting point, so I could start making improvements from there.

  1. Built a simple starting model first, just to have something working that I could measure everything else against.
  2. After every run I checked training loss, validation accuracy, and in later tests also top-5 accuracy. Having numbers to compare made decisions easier.
  3. Improvements went in a specific order: start simple, then try a stronger model, then tweak some settings to check for improvements. Doing it in that order meant I knew what was actually causing improvements.
  4. More advanced stuff like MixUp, EMA, gradient accumulation, and multitask learning only came in once the simpler things were working well. If I would make it complex from the start I would have no idea if it improved anything.
  5. Every run saved checkpoints and a history file. That meant I could go back and compare any two experiments, recover it when needed and warm start if I wanted some small tweaks to that model.

Training Pipeline

4. Training Methods Used

Even as the model type changed between tests, the core training loop stayed the same every time. That consistency made it easy to compare results fairly: if accuracy went up, I knew it was because of the specific thing I changed, not because the whole setup was different.

The process was always similar: start with a pretrained model, replace the final layer so it could predict 27 art styles, choose the training settings, train the model, and save the best version.

Transfer learning setup (tests 1-2, ResNet18 baseline)

Baseline: load pretrained ResNet18 and replace the head
weights = models.ResNet18_Weights.DEFAULT
model = models.resnet18(weights=weights)

# Replace the last layer with one that outputs 27 classes (one per art style)
in_features = model.fc.in_features
model.fc = nn.Linear(in_features, num_classes)
model = model.to(device)

criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-4)

Training and validation loop

The same function was used in every test to run one full pass through the dataset. During training the model updated its weights and learned from mistakes, while during validation it only measured performance without changing the model.

One function used for both training and validation
def run_one_epoch(model, loader, criterion, optimizer=None):
    is_train = optimizer is not None
    model.train() if is_train else model.eval()
    total_loss, total_correct, total_samples = 0.0, 0, 0

    for images, labels in loader:
        images, labels = images.to(device), labels.to(device)

        with torch.set_grad_enabled(is_train):
            outputs = model(images)
            loss = criterion(outputs, labels)

            if is_train:
                optimizer.zero_grad()
                loss.backward()
                optimizer.step()

        preds = outputs.argmax(dim=1)

        total_loss += loss.item() * labels.size(0)
        total_correct += (preds == labels).sum().item()
        total_samples += labels.size(0)

    return total_loss / total_samples, total_correct / total_samples

Top-1 and Top-5 accuracy

From test 4 onwards I also tracked top-5 accuracy. This checks whether the correct art style appeared in the model’s top 5 predictions instead of only the first prediction. With 27 classes this is more forgiving, but it still shows whether the model was close when it made a mistake.

Calculating top-1 and top-5 accuracy
def topk_accuracies(logits, targets, topk=(1, 5)):
    max_k = min(max(topk), logits.size(1))

    _, pred = logits.topk(max_k, dim=1, largest=True, sorted=True)
    pred = pred.t()

    correct = pred.eq(targets.view(1, -1).expand_as(pred))

    results = []

    for k in topk:
        kk = min(k, logits.size(1))
        correct_k = correct[:kk].reshape(-1).float().sum(0)
        results.append(correct_k.item() / targets.size(0))

    return results

Adaptation Techniques

5. Two-Stage Training

Training was done in two steps.

In step 1, only the final prediction layer was trained. The rest of the model stayed unchanged. This let the model first learn which visual patterns belong to the 27 art styles.

In step 2, the whole model was trained together. This allowed the deeper parts of the model to better adapt to paintings and improve accuracy further.

Train the final layer first, then train the whole model
def freeze_backbone(model, model_name: str):
    # Lock all weights
    for p in model.parameters():
        p.requires_grad = False

    # Unlock only the classification head
    for p in get_classifier_parameters(model, model_name):
        p.requires_grad = True


def unfreeze_all(model):
    for p in model.parameters():
        p.requires_grad = True


# Stage 1: train head only (5 epochs)
freeze_backbone(model, cfg.model_name)

optimizer_head = torch.optim.AdamW(
    filter(lambda p: p.requires_grad, model.parameters()),
    lr=cfg.head_lr
)

# Stage 2: fine-tune everything with lower learning rates
unfreeze_all(model)

optimizer_ft = torch.optim.AdamW([
    {"params": backbone_params, "lr": cfg.ft_backbone_lr},
    {"params": head_params,     "lr": cfg.ft_head_lr},
])
Smaller learning rates were used in stage 2 so the pretrained image knowledge was not changed too aggressively.

6. MixUp, CutMix, and Label Smoothing

These techniques were used to stop the model from becoming too confident on the training data. The goal was to help the model generalize better to new images instead of memorizing the training set.

  • MixUp: combines two images and their labels into one mixed training example.
  • CutMix: cuts part of one image and places it into another image, while also mixing the labels.
  • Label smoothing: makes the labels slightly softer so the model does not become too certain about every prediction.

7. Training Stability Techniques

These techniques were used to make training more stable, reduce overfitting, and improve accuracy.

Combining Smaller Training Steps

The ViT model with 384px images was too large to train with many images at once because of GPU memory limits. To solve this, the model processed 12 images at a time, but waited 4 steps before updating the weights. This made training behave more like using a batch size of 48 images.

Combining Smaller Training Steps (effective batch = 48)
accum_steps = cfg.effective_batch_size // cfg.batch_size  # = 4

optimizer.zero_grad()

for step, (images, labels) in enumerate(train_loader):
    images, labels = images.to(device), labels.to(device)

    images, soft_targets = mixup_cutmix(images, labels, ...)

    with torch.cuda.amp.autocast():
        logits = model(images)
        loss = criterion(logits, soft_targets) / accum_steps  # scale loss

    scaler.scale(loss).backward()

    if (step + 1) % accum_steps == 0:
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), cfg.grad_clip_norm)

        scaler.step(optimizer)
        scaler.update()

        optimizer.zero_grad()

        ema.update(model)  # update EMA weights after each real step

Early stopping

Early stopping automatically stopped training when validation accuracy stopped improving for several epochs. This helped avoid wasting training time and reduced overfitting.

Early stopping logic
best_val_top1 = 0.0
patience_counter = 0

for epoch in range(total_epochs):
    val_top1, val_top5 = evaluate(ema_model, val_loader)

    if val_top1 > best_val_top1:
        best_val_top1 = val_top1
        patience_counter = 0

        torch.save(ema_model.state_dict(), checkpoint_path)  # save best

    else:
        patience_counter += 1

        if patience_counter >= cfg.patience:
            print(f"Early stopping at epoch {epoch}")
            break

Test 9: Multitask Learning

8. Test 9: Training Three Tasks at Once

Test 9 is the most difficult experiment. Instead of just predicting art style, the model now predicts style, artist, and emotion all from the same image. The idea is that learning all three things at once should push the model to pick up on more visual detail than it would from style labels alone.

  • Style head: 27 art style classes (Impressionism, Cubism, etc.), same as every previous test
  • Artist head: predicts which artist made the painting, extracted from the WikiArt folder structure
  • Emotion head: 7 emotion classes (anger, disgust, fear, joy, sadness, surprise, trust), from the ArtEmis dataset

Handling missing emotion labels

Not every WikiArt image has an emotion label in ArtEmis. Rather than throwing those images away, I kept them and just skipped the emotion prediction for that row.

Combine three losses with learnable uncertainty weighting
# Compute individual losses
style_loss  = ce_style(style_logits, style_labels)
artist_loss = ce_artist(artist_logits, artist_labels)

# Only compute emotion loss where annotation exists
if has_emotion.any():

        emotion_logits[has_emotion],
        emotion_labels[has_emotion]
    )
else:
    emotion_loss = torch.tensor(0.0, device=device)

# Uncertainty-weighted combination (learned during training)
loss_total = (
    0.5 * torch.exp(-model.log_var_style)   * style_loss   + 0.5 * model.log_var_style   +

Why the 85.3% result looks misleading

Test 9 reports a style accuracy of 85.3%, which is much higher than test 8's 76.7%. But these numbers can't be fairly compared. The reason is that test 9 can only evaluate on images that exist in both WikiArt and ArtEmis, meaning only the subset that has a matching emotion label. That subset isn't random: it tends to contain the more famous, well-known paintings that are easier to classify. Rarer styles with fewer famous works are underrepresented in ArtEmis, so they show up less in the evaluation. In other words, the 85.3% is measured on an easier slice of the data, not the full validation set. It's a useful number for tracking how the multitask model is doing internally, but it doesn't mean the model suddenly got 8 points better at style classification overall.

Tests 11–12: New model

9. DINOv2 and Smarter Fine-Tuning

Tests 11 and 12 used a different pretrained model called DINOv2. Earlier tests used models trained with normal labeled image training, while DINOv2 learned from 142 million images by comparing images to each other without human labels.

This gave the model stronger visual features, especially for small visual differences between art styles.

Different learning rates for different layers

Not every part of the model was trained equally. Earlier layers already contained useful general image knowledge, so they were updated more slowly. Later layers were updated more strongly because they needed to adapt more to the art style task.

Earlier layers train more slowly than later layers
# Each transformer block gets a learning rate multiplied by decay^(depth from top)
llrd_decay = 0.75
base_lr    = cfg.ft_backbone_lr  # e.g. 1e-4

param_groups = []

for block_idx, block in enumerate(reversed(model.backbone.blocks)):
    lr = base_lr * (llrd_decay ** block_idx)
    param_groups.append({"params": block.parameters(), "lr": lr})

# The later (top) blocks train faster, early blocks train slower

Using larger image sizes

Test 12 increased the image size from 336px to 448px. Larger images contain more visual detail, which helped the model better recognize fine differences between painting styles.

Test 12 also started from the trained weights of test 11 instead of starting from scratch, so it reached good results faster.

Test 12 reached 78.3% validation accuracy, the best result across all experiments.

Responsible Development

11. Security, Privacy, Ethics, and Compliance

The model training side is well in hand, but if this ever turns into a real app where users upload images, there are extra things that need to be in place. Here's an honest breakdown of what's already covered in the notebooks and what would still need to be built.

Area What's already handled What still needs to be added
Security The prediction system is simple and isolated: load the model, process the image, and return the prediction. It does not make external connections or save files during prediction. For uploads: make sure the uploaded file is really an image, limit upload size, and clean filenames to avoid security problems.
Privacy The model does not use personal data. It only analyzes the image itself. The training data came from public art datasets such as WikiArt, ArtBench, and ArtEmis. For a real application: do not keep uploaded images longer than necessary, clearly explain how images are used, and avoid storing personal information with uploads.
Ethics The art style labels are clearly defined and based on the WikiArt dataset. The training process and evaluation results were fully documented. Predictions should include a confidence score so users can see when the model is uncertain, especially for very similar styles.
Compliance Training settings, saved models, and accuracy results were recorded for every experiment so the full training history can be tracked. For deployment: keep track of which model version and dataset version are being used, and document future model updates.

12. Conclusion

Going from 53% to 78.3% accuracy across 12 experiments wasn't done all at once. It was a series of smaller improvements over those tests. The early tests were mostly about getting a starting point: proper data loading, a working training loop, saving checkpoints. Once that was working, the focus shifted to stronger models and then better training techniques.

The biggest single jump was between test 5 and test 6, which came mostly from training longer and with different models, not from any exotic technique. That's a reminder that basic things like training duration often matter more than the fancy stuff.

The second biggest improvement came from switching to DINOv2 in tests 11 and 12. DINOv2's stronger visual features made a big difference, especially when combined with larger 448px images in test 12.
